## الهدف
بناء **هيكلة تأسيس قابلة للتوسع** بنمط واضح، وليس النظام كاملاً.

المرحلة أ تشمل فقط:
- البنية التقنية
- RBAC
- سجلات التدقيق
- لوحة نظرة عامة
- إدارة الفريق

لا يوجد نظام قديم للربط معه.

---

## القرار المعماري الثابت

| الجانب | القرار |
| --- | --- |
| النمط | Modular Monolith (NestJS واحد، وحدات بحدود واضحة) |
| قواعد البيانات | PostgreSQL خادم واحد + **قاعدة مستقلة لكل قسم رئيسي** |
| ORM | Prisma (عميل منفصل لكل قاعدة) |
| الواجهة | Next.js App Router + TypeScript + RTL عربي |
| المصادقة | JWT Access + Refresh + RBAC |
| Cache / Queue | Redis + BullMQ (تجهيز) |
| Real-time | Socket.IO namespace جاهز |
| التشغيل الافتراضي | **Native على Linux Server** (systemd / pnpm) |
| Docker | اختياري للتغليف أو بيئات معزولة — ليس شرطاً |
| تنظيم الكود | **مجلد باسم كل قسم** + ملفات حسب الدور/المهمة — ممنوع التكديس |

### قواعد قواعد البيانات
- لا Foreign Keys عبر قواعد مختلفة
- الربط عبر UUID فقط
- العمليات العابرة للأقسام عبر Application Service في NestJS
- كل قسم يملك migrations وPrisma schema خاصة

### قواعد تنظيم المجلدات والملفات
- لكل قسم رئيسي مجلد مستقل في: `modules/<section>` و `prisma/<section>` و `features/<section>`
- داخل القسم: `controller/` و `service/` و `dto/` منفصلة حسب المهمة
- لا تُكدَّس مهام غير مترابطة في ملف واحد — التفاصيل في [CODING_ORGANIZATION.md](./CODING_ORGANIZATION.md)
