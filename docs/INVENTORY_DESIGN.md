# تصميم نظام المخازن (مخزن واحد + أجهزة متسلسلة)

وثيقة تأسيس لقسم **مخازن** مستقل عن الصيانة.

## 1) الهدف

معرفة:

- ماذا لدينا في المخزن (أصناف + أجهزة بأرقام تسلسلية)
- لدى من الجهاز حالياً (فني / مخزن / مركّب على أصل)
- لمن صُرف ومتى ولأي أمر عمل
- توثيق كامل عبر أوامر توريد/صرف + دفتر حركات

## 2) نطاق المرحلة الأولى

### داخل النطاق
- مخزن واحد فقط (سجل `Warehouse` ثابت يُنشأ تلقائياً)
- أصناف: استهلاكية (`consumable`) أو متسلسلة (`serialized`)
- أجهزة متسلسلة: رقم تسلسلي + حالة + حامل + ربط أمر عمل / أصل صيانة
- أوامر: توريد | صرف | إرجاع | تعديل
- مسار المستند: `draft` → `posted` (الرصيد يتغير عند الاعتماد فقط)
- دفتر حركات append-only
- ربط اختياري بأمر عمل / طلب قطع (`workOrderId`, `partsRequestId` كـ UUID بدون FK عبر DB)

### خارج النطاق الآن
- تعدد المخازن / أرفف / نقل قيد النقل
- أوامر شراء وموردين كاملة
- تسعير / محاسبة / FIFO
- باركود متقدم

## 3) التمييز عن الصيانة

| المخازن | الصيانة |
| --- | --- |
| `Item` / `DeviceUnit` — ماذا نملك | `Asset` — أين نعمل (موقع/مشترك) |
| صرف وتوريد | بلاغ → أمر عمل |
| حامل الجهاز (`holderUserId`) | فني أمر العمل (`assigneeUserId`) |

`Asset` في الصيانة يبقى مرجعاً تشغيلياً خفيفاً داخل نماذج البلاغ/الأمر فقط — **ليس** قائمة مخزون.

## 4) الكيانات

```text
Warehouse (واحد)
Item ── StockBalance
     └── DeviceUnit (إن كان serialized)
StockDocument ── StockDocumentLine
              └── StockMovement (ledger)
```

### حالات الجهاز `DeviceUnit.status`
| الحالة | المعنى |
| --- | --- |
| `in_stock` | في المخزن |
| `issued` | مصروف لحامل (فني) |
| `installed` | مركّب على أصل صيانة |
| `faulty` | تالف |
| `scrapped` | مستبعد |

### أنواع المستند
| النوع | أثر الرصيد |
| --- | --- |
| `receipt` | + |
| `issue` | − (يتطلب `issuedToUserId` و/أو `workOrderId`) |
| `return` | + (إعادة من فني) |
| `adjustment` | ± (سبب إلزامي) |

## 5) قواعد ذهبية

1. لا يتغير الرصيد إلا عند `posted` داخل transaction.
2. الصنف المتسلسل: كل وحدة = جهاز واحد برقم تسلسلي فريد.
3. الرصيد السالب مرفوض.
4. الحركات غير قابلة للتعديل/الحذف.

## 6) الصلاحيات

| الرمز | المعنى |
| --- | --- |
| `inventory:read` | عرض |
| `inventory:manage` | أصناف + تعديلات + إدارة كاملة |
| `inventory:receive` | توريد / إرجاع |
| `inventory:issue` | صرف |

`inventory:manage` يستلزم كل صلاحيات المخازن.

## 7) الربط بالصيانة

عند صرف مرتبط بـ `workOrderId` / `partsRequestId`:
- يُحفظ المرجع على المستند والجهاز
- يمكن لاحقاً تعليم `PartsRequest` كـ `fulfilled` من واجهة الصرف

## 8) الواجهة

قسم رئيسي **مخازن**:
- لوحة أرصدة
- الأصناف
- الأجهزة (أين هي / لدى من)
- أوامر التوريد والصرف
- سجل الحركات
